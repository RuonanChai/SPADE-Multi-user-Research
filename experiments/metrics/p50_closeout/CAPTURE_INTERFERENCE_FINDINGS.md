# 432 次画布采集

独立重算，不沿用上传 CSV 的汇总数。A 臂 N=216，p50=376 ms，p95=499 ms，最大 591 ms，均值 376.23 ms。B 臂 N=216，p50=379 ms，p95=510 ms，最大 686 ms，均值 381.45 ms。

`capture_ms` 是 `captureCheckpoint` 入口到写完 JSON 的整段墙钟。源码里没有两枚时间戳能分开：等待下一帧、`gl.readPixels`、主线程翻转和 base64、Playwright 传回、PNG 编码、写盘。这些阶段都不能单独报成已测时长。`readPixels` 发生在渲染钩子里，调用是同步的，但没有单独的开始和结束时刻。

采集窗口用客户端 `trace_origin + trace_relative_s` 作为结束，再减去 `capture_ms` 得到开始，然后加上该观看者 `READY.json` 的 `clock_offset_ms` 对齐到代理时钟。与代理请求区间相交的请求记为重叠。这是同一会话里的时间邻近，不是因果证明。383 个有重叠请求的检查点里，重叠跨度更高的是 196 个，更低的是 180 个，相等 7 个；差值中位数是 +1 ms，范围 -163 到 1312 ms。另有 49 个检查点在对齐后的窗口里没有相交请求。看不出采集窗口稳定地抬高代理跨度。这里的 p50 用 ceil 分位，A 臂是 376 ms；偶数样本的算术中位数可以是 376.5 ms。均值和最大值与上传表一致。

两臂采集中位数只差约 3 ms。这个差值本身远小于 P2 浏览器完成时间 0.056–0.183 秒的臂间差距，而且 P2 两臂都做了同类读回。不能把 12/12 完成时间变慢写成“只有 SPADE 在截图”。
